# The Past Was Ridiculous

The scheduled workflow automatically creates original narrated archival shorts, refills from checked Prelinger sources, and publishes to configured channels on the existing three daily slots. Master publishing switches and verification checks remain in place; no per-video approval is required. See [Archive pipeline setup and operation](ARCHIVE_PIPELINE.md).

## Legacy dad-joke pipeline (retained for reference)

Automated pipeline that posts two dad joke videos a day to YouTube Shorts, then auto-cross-posts to TikTok and Instagram via Publer reading the RSS feed.

Each run:
1. Pulls a clean dad joke from r/dadjokes (Gemini fallback if nothing usable).
2. Generates voiceover with ElevenLabs.
3. Animates the "Hank" avatar talking via the HeyGen API.
4. Renders intro/outro cards + on-screen captions with ffmpeg.
5. Uploads to YouTube as a Short.
6. Updates `feed.xml` so Publer auto-posts to TikTok and Instagram.

The previous political-news version of this pipeline lives on the [`political-archive`](https://github.com/energeticcity/youtube-political-pipeline/tree/political-archive) branch.

## One-time setup

1. **Generate Hank's portrait** (the dad character). Save as `dad_avatar.jpg` in the repo root.
2. **Upload Hank to HeyGen as a Photo Avatar.** Avatars → Create Avatar → Photo Avatar → upload `dad_avatar.jpg`. Copy the avatar ID and set as `HEYGEN_AVATAR_ID`.
3. **Sign up for HeyGen Creator API tier ($24/mo)** for API access. Generate an API key under Space Settings → API. Set as `HEYGEN_API_KEY`.
4. **Pick a dad voice on ElevenLabs.** Browse the voice library for a warm middle-aged male voice. Set `ELEVENLABS_VOICE_ID`.
5. **Set up Make.com for Instagram + YouTube auto-posting** — see [MAKE_SETUP.md](MAKE_SETUP.md) for detailed step-by-step instructions. Free tier covers both platforms. Replaces both Publer and the in-pipeline YouTube OAuth.
6. **TikTok = manual upload.** Each pipeline run creates a GitHub Issue ("📱 TikTok upload ready") with a phone-friendly download link and a copyable caption. Open the issue email on your phone, save the video, upload to TikTok, add a trending sound. ~30 sec per video.

## Making the avatar more lifelike

Three levers, ranked by impact:

### 1. Better source photo (free, biggest impact)
HeyGen's lip-sync quality is bottlenecked by the source image. The current Hank was AI-generated by Gemini, which works but isn't ideal. For a more realistic talking head:
- **Use a real photo if possible** — even a friend or family member willing to be the face. Real faces always lip-sync better than AI-generated ones.
- **If staying with AI**: use Midjourney v6+ or Flux with explicit photorealism cues — "shot on Canon R5, 85mm lens, natural studio lighting, slight skin texture, real photograph"
- **Mouth slightly parted** in the source. Closed-mouth photos force HeyGen to generate teeth from scratch every syllable, which causes artifacts.
- **Looking directly at camera** (not 3/4 angle) — better lip alignment.
- **Even soft lighting**, no harsh shadows on the face.
- **High resolution** (2048×2048 minimum). HeyGen downsamples but works from the best version it has.

After generating: upload to HeyGen → Avatars → Create → Photo Avatar. Update `HEYGEN_AVATAR_ID` secret.

### 2. Enable Avatar IV mode (paid, +50-100% per video)
HeyGen's Avatar IV model adds head sway, natural blinks, micro-gestures, and subtle expression matching to the same Photo Avatar. To enable:
- Add GitHub Secret `HEYGEN_USE_AVATAR_IV` = `true`
- Optionally add `HEYGEN_MOTION_PROMPT` to direct behaviour, e.g. *"A friendly dad delivers a joke. Natural blinks, subtle head movements, warm smile, slight knowing nod when the punchline lands."* (default is similar)
- Verify your HeyGen plan supports Avatar IV credits — it costs more per render than the base talking_photo
- **Watch the budget alerts** — at ~2x cost per video, your $25/mo budget shifts from 100 → 50 videos. Drop cadence to 1-2/day or top up credits.

### 3. Multiple Hank expression variants (free, see "Adding extra Hank expressions" below)

## Adding extra Hank expressions (optional, makes videos more lively)

Out of the box the pipeline uses one Hank photo for every video. For variety, you can create additional HeyGen Photo Avatars with different expressions and the pipeline will rotate between them automatically.

1. Generate 2–4 new Hank photos in Midjourney. Use the same base prompt but change the expression. Suggested variants:
   - **Surprised**: "...wide-eyed with a surprised open-mouth smile, eyebrows raised..."
   - **Facepalm**: "...palm on forehead, eyes closed, wincing smile..."
   - **Sly smirk**: "...one eyebrow raised, knowing half-smirk, eyes looking slightly off camera..."
   - **Laughing**: "...head tilted back mid-laugh, eyes crinkled shut..."

2. For each photo: HeyGen dashboard → **Avatars** → **Create Avatar** → **Photo Avatar** → upload → note the avatar ID.

3. Add GitHub Secret `HEYGEN_AVATAR_IDS_EXTRA` as a comma-separated list, e.g. `a8d7e2f...,b9c3a1d...,c4e6d2f...`. The default `HEYGEN_AVATAR_ID` stays as-is.

4. Next pipeline run picks one of (default + extras) per video based on joke text. No duplicate renders back-to-back.

## GTA6 publishing

Production currently uses direct reposts with original audio and creator credit
(`GTA6_COMMENTARY_ENABLED=false`). Destinations are TikTok and Instagram
@gtaviclipfix and YouTube channel UCdL4ljG4SqfEA8qk5yd6v5w. TikTok uses pinned
Autotok 2.1.0 with the bounded session/endpoint compatibility patch; Instagram
uses pinned social-auto-upload with its browser regression patch. YouTube
currently uses the existing Post for Me connection. The optional YouTube CLI
and commentary modes below remain disabled.

A recovered publication skips completed destinations. Explicit TikTok rejections
may be retried after diagnosis; accepted or uncertain attempts remain reserved.
An Instagram authentication failure stops before upload. Never remove a
successful destination receipt to retry an entire batch.

### Optional commentary production

The separate `gta6-hourly.yml` workflow can turn reviewed GTA6 sources into original
visual commentary using `gta6/produce.py`. It reuses the existing Gemini and
ElevenLabs integrations; FFmpeg creates the 1080×1920 video, and ElevenLabs'
character alignment supplies caption timing. Original source audio is omitted.

Run `preview-commentary` from the GTA6 workflow to produce a sample without
posting. The `gta6-commentary` artifact contains the video, script, captions,
visual evidence notes and a fingerprinted quality receipt. Successful previews
are associated with their source in queue issue 266 and reused for publication.
Only successful main-branch workflow artifacts with matching source/output
fingerprints and quality results are accepted.

Set repository variable `GTA6_COMMENTARY_ENABLED=true` to use this production
step for scheduled publications. Sources must provide 20–60 seconds of footage.
Each attempt permits two script drafts at most, one narration request and one
finished-video review. Narration is 50–65 words and must fit 20–60 seconds.
The final check inspects actual video orientation, readable captions, supported
observations and complete audible narration. Rejection never falls back to a
raw repost. Editorial failures are removed from the ready queue; service
outages leave the source available for a later run.

Existing posting hours, the 12-post daily cap, exact account guards and durable
duplicate reservations remain in effect. Production failures can mean fewer
than 12 posts. Costs use the existing Gemini/ElevenLabs accounts; at the maximum
600 narration characters per post, 12 newly generated posts use at most 7,200
TTS input characters per day, plus model calls and GitHub Actions runtime.

The GTA6 hourly publisher checks the ledger every five minutes, away from minute zero.
A cheap gate skips media/browser setup when the current local hour is already reserved.
Only one batch is allowed per hour from 8 a.m. through 7 p.m. Dawson Creek time,
with a 12-batch daily cap. Discovery is attempted once per morning and afternoon
window, beginning at 7 a.m. and 3 p.m. Delayed checks do not burst-post missed hours.
A timer configuration alone is not proof of execution: verify scheduled workflow runs
and each platform receipt. Direct repost mode remains the production setting.
